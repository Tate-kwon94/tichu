# 사람다움 개선 플랜 (①②③④) — v8 체인 결과 확정 후 진행

> 사용자 지시: 현재 v8 체인 결과 나온 뒤 착수 여부/순서 결정. 실행 전 검토 완료 상태.

## 배경 — 사용자가 짚은 "봇이 사람에 못 미치는" 지점
카드게임 실력의 본질 = **패의 적재적소(아끼기) · 상대 패 읽기 · 블러핑**. 현재 봇은 전술(조합·완주·선언)은 정확하나 이 세 가지가 약함.

## 3층 구조 (용어 확정, 코드 기준)
- **턴(수)**: 한 번 내기/패스 (`_playCards`/`_pass`)
- **라운드**: 패 한 벌 8→14장 다 털 때까지, 끝에 정산 (`_startRound`→`_endRound`)
- **게임**: 목표점수(1000 등)까지 여러 라운드 (`scores`≥`targetScore`→`gameOver`, tichu-core.js:649)
- 봇의 평가(hybrid-bot.js:54,97)·학습타깃(gen-champion.js:56 `out=라운드 점수차`)이 **라운드에서 잘림** → 게임 맥락 없음. 카드 아끼기엔 라운드리셋이라 게임맥락 마이너, 단 **선언 위험조절엔 결정적**.

## 공통 원칙
- **검증 = 승률(회귀방지) + 체감(주지표)**. raw 승률은 휴리스틱 천장이라 잘 안 오름 — 정성 시나리오가 핵심.
- **단 사다리**: 개선 봇을 고정 1단(v6-PUCT) 상대 측정. 65%+면 2단. 승률중립+체감↑면 사용자 결정. ①②③ 누적하면 65% 넘길 수 있어 묶음 판정 권장.

## Phase 1 — 선언 위험 조절 (②의 선언 부분) ⭐ 최우선
- 목표: 게임 점수차로 티츄/라지 임계 동적화 — 뒤지면 공격(도박), 앞서면 보수(자제)
- 접근: declare.js tichu()/grand() 고정임계(0.50/0.52)→점수차 함수. `임계 += k·(내−상대)/목표`. 규칙기반 시작
- 검증: 950:300 손패 선언율↓ / 300:950 선언율↑. 승률 중립~소폭
- 난이도: 낮음·반나절. 리스크: 과하면 무모선언→k 튜닝
- 체감 즉효: "지고 있으니 지르네"

## Phase 2 — 보유 가치/아끼기 (①) ⭐
- 목표: 강카드(A·폭탄·용) 쥐고 있으면 잠재가치+, 게임진행할수록 감쇠. 낭비페널티의 능동적 반대편
- 접근: hybrid-bot.js heuristicPlayout 평가에 손패 보유가치 항. 또는 가치헤드 보조타깃
- 검증: 푼돈에 A 안냄, 위협시 냄. 승률 중립~소폭
- 난이도: 중간·1일. 리스크: 과하면 끌어안다 라운드놓침→감쇠곡선 튜닝
- Phase1+2 합치면 "평소 아끼다 위협시 터뜨린다" 리듬 완성

## Phase 3 — 상대 패 읽기 (③)
- 목표: determinize를 무작위→관측(플레이·패스)과 모순없는 패로 제약
- 접근: "rank9 싱글에 패스→9초과 싱글 없음(폭탄예외)" 규칙을 결정화에. 발전형: belief network 샘플링
- 검증: 결정화가 관측과 모순없는지 + 실제 승률↑ (진짜 강해짐, 체감아님)
- 난이도: 어려움·2~3일. 리스크: 제약 틀리면(폭탄/불사조 예외) 편향→오히려 약화. 신중검증
- 실제 실력↑ → 2단 승단 진짜 후보

## Phase 4 — 블러핑 (④) ⚠️ 별도 대형
- 목표: 혼합전략 예측불가성
- 접근: CFR 계열(PUCT/모방과 다른 알고리즘). 티츄 전체 CFR 난망→"제한적 무작위화" 정도
- 정직한 권고: 티츄는 패스·조합 위주라 포커만큼 블러핑 여지 작음. 과투자 위험. **①②③ 후 재평가 결정**

## 실행순서 & 타임라인
1(반나절)→2(1일)[여기서 1+2 묶어 1단상대 측정]→3(2~3일)[1+2+3 묶어 65% 승단전]→4(재평가). 총 ①②③ ≈ 1주.

## 판단 포인트
1. 개별배포(①② 체감 반응수집) vs 묶음판정(③ 실력 승단). 권장: ①②개별, ③묶음
2. RL과 관계: ②③은 오라클RL이 자동학습하는 것과 겹침. ①②③=빠른 휴리스틱버전, RL=근본학습버전. ①②③ 선행 후 부족하면 RL(2단 로켓)
