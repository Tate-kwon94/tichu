# 4단 — "계속 돌리는" 자가대전 검토와 AZ 루프 설계 (2026-07-28)

사용자 요청: 3안(사람 기보) 기본 + "RL이나 자가대전 같은 것도 계속 돌리고 싶다."
이 문서는 상시 가동 후보 4개의 정직한 판정과, 채택 시 즉시 착수 가능한 설계다.

## 1. 상시 가동 후보 판정 (전부 기존 실측 기반)

| 후보 | 판정 | 근거 (실측) |
|---|---|---|
| RL2 연장 (best-response, raw축) | **기각** | 16세대 raw +0.87~+4.02 요동에도 PUCT 실물 +0.10±2.08 — 전이 계수 ~0. 더 돌려도 같은 벽 |
| 리그/모집단 자가대전 (프라이어 축) | **단독 기각** | 병목은 과적합이 아니라 전이 벽 — 모집단은 벽을 안 건드림. AZ의 평가층으로만 채용 |
| 오라클 라벨 파밍 (가치망 대형화) | **기각** | v_net 리프 교체 37.5%, MLP·deepThink 3연속 프록시≠실물 — 프록시를 더 정확히 근사할수록 프록시 천장에 수렴 |
| **AZ식 PUCT-in-the-loop 자가대전** | **유일 후보** | 아래 §2 — 전이 문제를 구조적으로 제거(배포 시스템 자체를 훈련). 단, 기대값은 정직하게 "0 근처 + 우상단 꼬리" |

## 2. AZ 루프 — 왜 유일하게 살아있고, 왜 기대값이 낮은가

**살아있는 이유**: 지금까지 죽은 축은 전부 "배포봇 밖에서 좋아진 것을 안으로 이식"이었다
(raw 정책, 오라클 라벨, 대리 평가 최적화). AZ는 **배포봇(PUCT 950ms)이 실제로 낸 결론
(방문 분포)과 실제 결과(라운드 점수)를 그대로 학습 타깃**으로 쓴다 — 이식 단계가 없다.

**기대값이 낮은 이유**: 로드맵 §1의 천장 기전 — PUCT는 이미 플레이아웃 평가의 최선수를
실현한다. 탐색이 이미 최적이면 그 결론을 배워도 같은 수를 둔다(개선 0으로 수렴, 해는 없음).
개선이 나오는 경로는 하나뿐: **프라이어 캘리브레이션**(현재 pmax 0.726 과확신, 시뮬 84%가
1순위 집중 → 분포 타깃이 이 낭비를 풀면 같은 950ms에서 유효 탐색 폭이 넓어짐).
자기증류 천장(v7 55%·v8 47.5%)이 반대 증거지만, 그때는 argmax 모방(분포·가치헤드·반복 없음).
**정직한 성공률 ~10-15%.**

**복권이어도 무가치하지 않은 이유 (채택의 실질 근거)**:
루프의 데이터 스키마 (상태, 타깃 분포/선택, 결과) = **사람 기보 학습 파이프와 동일**.
3안이 본론이 될 때(수 주 뒤) 이 인프라를 그대로 재사용한다 — 사람 결정을 타깃으로 바꾸면
모방 미세조정, gamelog-vs-bot 지도와 결합하면 국면 한정 학습. 즉 AZ 루프 구축 = 3안 선행 투자.

## 3. 처리량 (실측 환산)

- 생성: 950ms 4좌석 PUCT 게임 ≈ 10~15분/게임/vCPU. CI 20러너×4vCPU 야간 3h ≈ 800~1,400게임.
- 샘플: 게임당 유효 플레이 결정 ~300 (10~12라운드 × 4좌석 × ~7 유의미 결정) → 야간 25~40만.
- 로컬 맥(8스레드, 뚜껑 열고 전원): 하룻밤 ~150게임 ≈ 4.5만 샘플 + 학습(M2 MPS, 기존 파이프).
- 1세대 = 신선 50~100만 샘플이면 CI 2~3일 야간 배치. **주 2세대 페이스.**

## 4. CI 사용 원칙 (약관·상도의)

GitHub Actions 공개 repo 무료는 "프로젝트 개발 활동" 전제. 봇 측정·학습 데이터 생성은
경계 안이지만 **24/7 상시 점유는 금지선** — cron 야간 1회(≤3h) + 수동 디스패치만.
상시 그라인딩이 필요하면 로컬 맥 담당(caffeinate, 기존 rl 루프 방식).

## 5. 구현 목록 (다음 세션, 승인 시)

1. `hybrid-bot.js` decidePuct에 방문 분포 노출(`opts.wantStats` → {acts, visits, value}) — 프로덕션 경로 무변경(옵트인).
2. `ml/gen-az.js` — 4×PUCT(예산 인자) 자가대전, (상태 인코딩, 방문분포, 라운드 결과) JSONL. CRN 시드 주입.
3. `ml/train_az.py` — train_pilot 확장: 정책 = 분포 교차엔트로피, 가치헤드 = 결과 회귀, v6/swa 앵커 KL.
4. `.github/workflows/selfplay.yml` — 야간 cron 1회 + dispatch, 20샤드, 산출물 아티팩트.
5. `ml/az.sh` — 로컬 루프(생성→학습→raw 짝지음 트립와이어→PUCT 스팟체크).
6. **사전등록 킬게이트**: ①세대별 실물 스팟(PUCT 짝지음 240게임): 3세대 연속 CI가 0을 포함하고 점추정 <+1이면 접는다 ②최종 판정은 언제나 CI 960게임 사전등록(53% = +4.17, 또는 사용자가 52% 완화 결정 시 +2.8).
7. 접으면: 인프라는 3안(사람 기보 미세조정)용으로 전환 — 손실 아님.
